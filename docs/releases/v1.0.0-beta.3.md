RadioGeddon v1.0.0 Beta 3

> [!WARNING]
> **Pre-release, not yet verified on hardware.** Everything new in this beta
> passes the automated checks below, but none of it has been tried on a
> physical Flipper Zero yet. The only device report so far is for the beta 2
> code on RogueMaster (it launches and works). Use only on devices you own or
> are authorized to test, and please report what you find with the
> [hardware checklist](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md).

## What's new

Beta 3 brings milestones 1 to 9 of the
[roadmap](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/ROADMAP.md).
The full list is in the
[CHANGELOG](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/CHANGELOG.md).

- **Scanner**: per-frequency noise floor, activity detection with an
  adjustable threshold, peak hold, burst counts, custom scan lists and dwell,
  hold on the first active frequency, pause, and CSV export to the SD card.
- **Frequency Hopper**: custom hop lists, dwell and hold times, noise-floor
  detection, lock and step, a statistics screen, and optional automatic RAW
  recording of each burst of activity.
- **Recording**: RAW captures stream to the SD card while recording, so their
  length is limited by the card, not by memory. Samples are never dropped
  silently: any loss is counted on screen and in the file.
- **Analysis**: Unknown Protocol Analysis reads the whole capture, tries PWM,
  PPM and Manchester on every frame with a confidence score, groups repeated
  frames, and labels measurements `[OBSERVED]` and inferences `[HYPOTHESIS]`.
  A new **Pulse Timeline** shows a capture as a zoomable waveform.
- **Database**: a sortable, filterable list with search, duplicate marks,
  file details, rename, damaged-file handling, and analysis reports saved to
  the SD card.
- **Interface**: progress percentages for long jobs, clearer messages, and
  settings saved between launches.
- **External CC1101 module**: optional, through the firmware's own driver,
  used only when a module answers, with the region check kept for transmit.
- **Memory**: figures in About. Receive and the Hopper measure what a radio
  session needs and, once measured, refuse to start with `Not enough memory`
  when it no longer fits, instead of risking the crash beta 1 had.
- **Fixes found by the new tests**: RAW files written with commas
  (`RAW_Data: 1718, -32700, ...`, which the firmware's player accepts) now
  read in full; an out-of-range value in a damaged file no longer overflows;
  a failed save never leaves a partial file or replaces an existing one.

Settings are stored in `apps_data/radiogeddon/settings.txt` (new). Recordings
stay in `apps_data/radiogeddon/signals`, so files from earlier betas appear in
the Database.

## Which file do I download?

Install the build that matches your firmware. The others are safely refused by
the Flipper rather than loading.

| Firmware | File | API |
|----------|------|-----|
| Official (flipperzero.one) 1.4.x | `radiogeddon-official.fap` | 87.1 |
| Unleashed | `radiogeddon-unleashed.fap` | 88.9 |
| RogueMaster | `radiogeddon-roguemaster.fap` | 88.16 |

Copy it to `SD Card/apps/Sub-GHz/` (replacing the earlier beta) and open
**Apps → Sub-GHz → RadioGeddon**. Full steps:
[Installation](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/INSTALLATION.md).

> [!NOTE]
> Official firmware **1.5.1** (now a release candidate) moves to API 88, so
> `radiogeddon-official.fap` will not load on it. The app builds against the
> 1.5.1-rc SDK, but no release build targets it yet; see
> [Firmware Compatibility](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/FIRMWARE_COMPATIBILITY.md#newer-firmware)
> to build it yourself.

## Build & verification status

- Built for Official, Unleashed and RogueMaster from one source tree, each
  against its own SHA-256-pinned SDK; API version and `.fap` manifest verified
  for every artifact.
- 532 host unit-test checks under AddressSanitizer and UBSan; 562 format
  checks that run the firmware's own file code on its 85 Sub-GHz test files;
  libFuzzer runs on the RAW reader, analyzer, Pulse Timeline and Database;
  GCC `-fanalyzer` and clang-tidy with no findings; lint and documentation
  links clean.
- Hardware: not verified for anything new in this beta. See
  [VERIFICATION.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/VERIFICATION.md).

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or the
per-file commands in the installation guide. Each `.fap` also has a signed
build-provenance attestation, checked by the release workflow before upload,
linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-official.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the SDK, API and source revision each artifact was
built from.

## Known limitations

- Nothing new in this beta is verified on a device yet; radio timing, SD-card
  speed and memory headroom on real hardware may surface problems the host
  tests cannot.
- The encoding Unknown Protocol Analysis reports is a hypothesis. On the
  firmware's own test captures its frame length matches the decoded bit count
  for 8 of 33 paired captures, and is one bit short for 5 more.
- Unplugging an external module while receiving is not supported by the
  firmware's driver.
- RadioGeddon does not recover keys, decrypt payloads or predict rolling
  codes, and refuses to replay decoded rolling-code protocols.
