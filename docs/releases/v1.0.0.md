RadioGeddon v1.0.0 — Stable

RadioGeddon 1.0.0 is the first stable release of the standalone Sub-GHz
signal analysis toolkit for the Flipper Zero. It is the beta 13 application
code — the memory and relaunch release — published as a stable version:
no feature was added or removed for it, and every transmit restriction is
unchanged. From here the project is maintained: bug fixes from reports,
firmware compatibility updates and optional feature updates.

## Highlights

- **Stability.** Beta 12 fixed the Adaptive Scanner crash and the relaunch
  RAM failure the owner logged on beta 11; beta 13 fixed the Logger refused
  after the Adaptive Scanner and the allocation order of Receive opened from
  a tool screen.
- **Memory.** Resident code on the RogueMaster `4f2e06200` build is
  66,003 B, down from 84,812 B in beta 12 (−22 %) and 119,132 B in beta 9.
  The app's code is five sections of 8–13.5 KB, so a launch needs much
  smaller free blocks; Receive takes about 10 KB less per session. The
  optional tools are 19 modules loaded only while their screen is open.
- **Compatibility.** Five builds from one source commit, each against its
  own pinned SDK or firmware tree: Official (Catalog edition), RogueMaster,
  the exact RogueMaster `4f2e06200` / API 88.4 device build, Momentum and
  Unleashed.
- **Feature set.** Both editions: Frequency Scanner, Frequency Hopper,
  receive and decode with the firmware's own decoders, streaming RAW
  recording, Decode with Firmware, Signal Analyzer, Unknown Protocol
  Analysis, Pulse Timeline, Signal Comparison, Signal Database, recording
  recovery, memory diagnostics and region-checked (Catalog) or
  firmware-authorized (Full) replay. Full edition in addition: Range
  Scanner, Waterfall, Favorites and scan profiles, Bitstream Explorer,
  Multi-Capture Compare, Research Sessions, Find Similar Signals, Pulse
  Studio, Smart Protocol Discovery, Adaptive Scanner, RF Activity Logger,
  Research Journal and the Dolphin Lab interface. The full list is in
  [Features](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/FEATURES.md).

## Hardware testing — what is and isn't confirmed

The owner ran this code (as beta 13) on a physical Flipper Zero with
RogueMaster `4f2e06200`, API 88.4, using
`radiogeddon-full-roguemaster-4f2e06200-api88.4.fap`:

- four launches and exits without rebooting the Flipper;
- the Frequency Scanner works;
- the Adaptive Scanner starts and stops, and the RF Activity Logger loads
  again after it (beta 12 refused it);
- beta 12's intermittent `Error loading section '.rgtext'` did not
  reproduce in those four launches;
- about 65.9 KB of sections loaded (beta 12: about 84.8 KB) and about
  45 KB of heap free after start;
- no crash. Occasional `ViewPort lockup` warnings appeared during brief
  screen-transition delays, without a lasting malfunction.

This is real but limited evidence. **Not yet tested on a device:** receive
and decoding against a remote, RAW recording, replay or any transmission,
most of the 19 modules, longer relaunch series, the other firmware builds,
and the Catalog edition on Official firmware. A 40-byte free-heap difference
seen in one session is recorded, but one reading does not establish a leak.
Details:
[VERIFICATION.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/VERIFICATION.md#reported-by-users-on-physical-hardware).
Reports from the
[hardware checklist](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md)
are welcome in the issue tracker. Use only on devices you own or are
authorized to test.

If *Settings → About → Firmware Info* shows `4f2e0620 [88.4]`, use the
device-specific RogueMaster build; on any other RogueMaster build use
`radiogeddon-full-roguemaster.fap`. Copy only one of the two.

Copy the file to `SD Card/apps/Sub-GHz/` (replacing the beta) and open
**Apps → Sub-GHz → RadioGeddon** (Catalog) or **RadioGeddon Full**.
Settings, recordings, sessions, the journal and the fingerprint index from
the betas keep working. Full steps:
[Installation](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/INSTALLATION.md).

> [!NOTE]
> Momentum and Official both report API 87.1, so the Flipper's version check
> does not tell the two files apart: install the one named for your firmware.

The Catalog edition is being submitted to the official Flipper Apps
Catalog. It is not listed there yet; until it is, install it from this page.

## Build & verification

- Five builds from one source commit, built from scratch. For every
  artifact the API version is asserted, the manifest checked and every
  imported symbol resolved against that firmware's `api_symbols.csv`; for
  the four Full builds the same holds for each of the 19 embedded modules.
- Host unit tests under AddressSanitizer and UBSan; the firmware's own
  Sub-GHz decoders on its test captures; format, capture, engine-lifecycle,
  fingerprint, activity-log, memory-stress and offline UI tests;
  ThreadSanitizer; libFuzzer on every file reader; firmware API contract
  checks; code-section checks; module load cost and heap-model replays;
  GCC `-fanalyzer` and clang-tidy; clang-format; the Apps Catalog's own
  rules and bundler on the Catalog edition.
- Automated checks are not device verification; see the hardware section
  above for what has been run on a Flipper.

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or
the per-file commands in the installation guide. Each `.fap` also has a
signed build-provenance attestation, checked by the release workflow before
upload, linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-full-roguemaster-4f2e06200-api88.4.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the edition, app id, SDK or firmware commit, API,
source revision and embedded modules of each artifact.

## Known limitations

- Hardware testing is limited to the session above; everything else is
  verified by automation only.
- Occasional `ViewPort lockup` log warnings during screen transitions on
  RogueMaster `4f2e06200`; not explained yet.
- Opening the Database, the Scanner, the analysis menu, the favorites or a
  research tool loads a module (a few tens of milliseconds); with very
  little memory left it says `Not enough memory` instead of opening.
- The module memory check sees only the largest free block.
- The device-specific RogueMaster file fits only commit `4f2e06200`.
- RadioGeddon does not recover keys, decrypt payloads, predict rolling codes
  or brute-force anything, and refuses to replay decoded rolling-code
  protocols. The Catalog edition transmits only where the firmware's region
  allows the frequency.
