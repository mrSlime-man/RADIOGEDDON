RadioGeddon v1.0.0 Beta 5

> [!WARNING]
> **Pre-release, not yet verified on hardware.** Everything in this beta
> passes the automated checks below, but nothing new since beta 2 has been
> tried on a physical Flipper Zero yet. The only device report so far is for
> the beta 2 code on RogueMaster (it launches and works). Use only on devices
> you own or are authorized to test, and please report what you find with the
> [hardware checklist](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md).

## What's new

Beta 5 fixes saved keys, makes Replay safer with custom presets, improves
Unknown Protocol Analysis and adds a typed frequency. The full list is in the
[CHANGELOG](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/CHANGELOG.md).

- **Fixed: saved keys open in the stock Sub-GHz app and in Replay.** Every
  key saved from *Receive & Record* or the Hopper by betas 1 to 4 was written
  as a custom preset with no settings in it, so the stock app says
  `Cannot parse file` and Replay refused it. Keys are now saved with the
  modulation they were received on. RAW recordings were never affected. Keys
  you saved earlier need a one-line edit, described in
  [Troubleshooting](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/TROUBLESHOOTING.md#a-saved-key-wont-open);
  until then Replay shows `Bad custom preset`.
- **Fixed: Replay checks a file's custom preset before loading it.** A
  `.sub` file can carry its own CC1101 register list, and the firmware
  writes it to the radio without checks. A damaged list made it read past
  the buffer, and an address that is a radio command rather than a setting
  would have run; `0x35` starts transmitting before the region check. Such
  files are now refused with `Bad custom preset` and nothing reaches the
  radio. Every preset the firmware ships passes the check.
- **Unknown Protocol Analysis reads real captures better.** Scored in CI on
  the firmware's own 50 RAW test captures against each protocol's decoder,
  it now gets the base time unit (Te) right for 48 (was 39), the encoding
  family for 41 (was 33) and the frame length within one bit for 29
  (was 16). Results stay labelled `[HYPOTHESIS]`.
- **Custom frequency**: press OK on `Frequency MHz` in Settings to type any
  frequency in kHz for *Receive & Record*. If the radio in use cannot tune
  it, the screen says `Cannot tune there` and nothing changes. Transmitting
  is still checked against the firmware's region rules.
- **Frequencies show their kHz**: 433.075 MHz now reads `433.075` in
  Settings, Receive, Replay, the Database list and the Hopper statistics,
  where it was cut to `433.07`.

Settings and recordings stay where beta 4 put them
(`apps_data/radiogeddon/`).

## Which file do I download?

Install the build that matches your firmware. The others are safely refused by
the Flipper rather than loading.

| Firmware | File | API |
|----------|------|-----|
| Official (flipperzero.one) 1.4.x | `radiogeddon-official.fap` | 87.1 |
| Unleashed | `radiogeddon-unleashed.fap` | 88.9 |
| RogueMaster | `radiogeddon-roguemaster.fap` | 88.16 |

Copy it to `SD Card/apps/Sub-GHz/` (replacing the earlier beta) and open
**Apps → Sub-GHz → RadioGeddon**. Full steps:
[Installation](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/INSTALLATION.md).

> [!NOTE]
> Official firmware **1.5.1** (still a release candidate) moves to API 88, so
> `radiogeddon-official.fap` will not load on it. The app builds against the
> 1.5.1-rc SDK, but no release build targets it yet; see
> [Firmware Compatibility](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/FIRMWARE_COMPATIBILITY.md#newer-firmware)
> to build it yourself.

## Build & verification status

- Built for Official, Unleashed and RogueMaster from one source tree, each
  against its own SHA-256-pinned SDK; API version and `.fap` manifest verified
  for every artifact.
- 665 host unit-test checks under AddressSanitizer and UBSan; 569 format
  checks that run the firmware's own file code on its 85 Sub-GHz test files;
  263 decoder checks that run the firmware's own decoders on its 50 RAW test
  captures, including every decode saved as the app saves a key; 26 checks
  of the custom preset check on the firmware's own presets; 354 checks that
  score the analyzer on the same captures; libFuzzer runs on the RAW reader,
  analyzer, Pulse Timeline and Database; GCC `-fanalyzer` and clang-tidy with
  no findings; lint and documentation links clean.
- Hardware: not verified for anything new since beta 2. The checks to run
  are F1f (custom frequency), F6g (saved keys in the stock app) and F7
  (custom-preset replay), plus F4g and F5a from beta 4; see
  [VERIFICATION.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/VERIFICATION.md).

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or the
per-file commands in the installation guide. Each `.fap` also has a signed
build-provenance attestation, checked by the release workflow before upload,
linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-official.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the SDK, API and source revision each artifact was
built from.

## Known limitations

- Nothing new since beta 2 is verified on a device yet; radio timing, SD-card
  speed and memory headroom on real hardware may surface problems the host
  tests cannot.
- Keys saved by betas 1 to 4 are not repaired automatically: the file does
  not say which modulation they were received on.
- The encoding Unknown Protocol Analysis reports is a hypothesis. Its known
  misses are listed in
  [Protocol Analysis](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/PROTOCOL_ANALYSIS.md#what-it-cannot-do):
  equal-width pulse codes read as Manchester, repeats with no gap stay one
  long frame, and two very noisy captures give a Te of 132 µs.
- The Scanner's frequency column still shows two decimals, to keep its bars
  readable.
- Unplugging an external module while receiving is not supported by the
  firmware's driver.
- RadioGeddon does not recover keys, decrypt payloads or predict rolling
  codes, and refuses to replay decoded rolling-code protocols.
