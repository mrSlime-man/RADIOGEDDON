## What's new

Beta 10 is an optimization release: the same features, in much less memory,
with files that survive a reboot. Nothing in it transmits on its own. The
full list is in the
[CHANGELOG](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/CHANGELOG.md).

- **Full edition 29 % smaller in memory** — its resident code drops from
  119,132 B to 84,313 B. Beta 9's Full edition did not start on some devices
  ("Out of memory"); the Range Scanner (with the Waterfall and scan
  profiles), Settings (with Radio bands), the Frequency Hopper, the
  Bitstream Explorer, About and recording recovery are now modules loaded
  from the `.fap` only while their screen is open, like the beta 9 tools.
  Nothing they do changed; opening one of them reads its module first.
- **Bitstream Explorer: 4 KB less at its peak** — it keeps the analysis
  instead of copying it, so the analyzer (8.7 KB) and a 4 KB copy are never
  in memory at once.
- **Recording recovery** (both editions) — a RAW recording cut off by a
  reboot or a flat battery is repaired (complete values only) and offered
  back at the next start: Keep, or Delete. Before, it was deleted.
- **Crash-safe saves** — settings, the journal, favorites, scan profiles and
  the fingerprint index: a reboot in the middle of a save leaves the old or
  the new version, never neither.
- **Faster Database and Find Similar** — sorting, searching and duplicate
  marking in O(n log n) (7–18× less work at 500–1,000 files on the host);
  the fingerprint index lists the folder once when nothing is new and now
  holds up to 2,000 recordings (was 500).
- **Find Similar scope** — all recordings, within 1 hour, within 1 day, or
  only the active research session's recordings.
- **RF Activity Heatmap** (Full) — a saved activity log as frequency × time,
  keeping "not observed" apart from "quiet".
- **Diagnostics report and Battery saver** (both editions) — About shows UI
  responsiveness, module loads, recording losses and SD write speed, and
  saves them as a report (counts only, no capture data); the battery saver
  redraws live screens at most twice a second (its battery effect is not
  measured).
- **Fixes** — data races on the engines' stop flags (found by
  ThreadSanitizer, now in CI); two recordings whose names had equal 32-bit
  hashes kept one out of the fingerprint index.

Every feature of beta 9 is kept: Dolphin Lab, every analyzer and research
tool, both editions and all four firmware builds.

## Memory

**Binary footprint**, measured from the built files (`scripts/fap_size.py`:
the code and static data the loader places in RAM). This is *not* the app's
runtime RAM, which also includes its heap, stack, the radio session and the
open tool's module and working memory, and which has **not been measured on
a device**:

| | Beta 9 | Beta 10 |
|---|---:|---:|
| Full edition, resident | 119,132 B | 84,313 B |
| Catalog edition, resident | 80,553 B | 86,513 B |
| Full modules | 10 | 16 |
| Largest Full module loaded at once | 21,904 B (Pulse Studio) | 23,620 B (Find Similar) |
| Bitstream Explorer while it opens, beyond the resident app (computed) | 19,464 B | 25,265 B |
| Bitstream Explorer while it opens, with the resident app (computed) | 138,596 B | 109,578 B |

The Catalog edition has no modules, so recording recovery (+2.4 KB), the
diagnostics and battery saver (+2.1 KB), crash-safe saves (+0.6 KB) and the
faster Database (+0.6 KB) are resident there: +5,960 B. Every tool checks
the free heap for its module and its work before allocating and says `Not
enough memory` when they do not fit.

## Build & verification status

- Built from one source tree as two editions for four firmware families, each
  against its own SHA-256-pinned SDK (RogueMaster from its pinned source
  tree). For every artifact the API version, the manifest and every imported
  symbol are verified against that SDK; for the Full builds the same holds
  for each of the 16 embedded modules (this check caught two resident-only
  functions the new modules called, fixed before release).
- 2,756 host unit-test checks under AddressSanitizer and UBSan (beta 9:
  2,528), with new suites for crash-safe saves (122), recording recovery (17)
  and the heatmap (61). Also: 701 format checks, 339 decoder and preset
  checks, 407 analyzer checks on the firmware's captures, 43 engine
  lifecycle checks, 85 fingerprint-index checks (with the session scope) and
  31 activity-log file checks through the firmware's own FlipperFormat and a
  stub SD card, 426 offline UI checks, the threaded tests under
  ThreadSanitizer (no reports), libFuzzer on every file reader, and GCC
  `-fanalyzer` and clang-tidy with no findings.
- Previews in the README are **synthetic renderings** from the host canvas,
  not screenshots of a Flipper.
- Hardware: **NOT HARDWARE TESTED.** The checks to run are in
  [HARDWARE_CHECKLIST.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md)
  and [VERIFICATION.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/VERIFICATION.md).

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or the
per-file commands in the installation guide. Each `.fap` also has a signed
build-provenance attestation, checked by the release workflow before upload,
linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-full-momentum.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the edition, app id, SDK, API, source revision and
embedded modules each artifact was built from.

## Known limitations

- **Not hardware tested**: in particular, that the Full edition now starts on
  the devices where beta 9 did not, how long each new module takes to load
  from the SD card, recovery after a real power loss, and the battery saver's
  effect on battery life.
- Opening the Range Scanner, Settings, the Hopper or the Bitstream Explorer
  now reads its module from the SD card first: a short pause the first time
  each is opened in a run.
- Similarity is evidence, not identity; the Adaptive Scanner's gains come
  from a host simulation; the activity logger observes one frequency at a
  time.
- The Catalog edition is not in the Apps Catalog yet: the submission needs
  qFlipper screenshots from hardware.
- RadioGeddon does not recover keys, decrypt payloads, predict rolling codes
  or brute-force anything, and refuses to replay decoded rolling-code
  protocols.
