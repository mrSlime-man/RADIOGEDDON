RadioGeddon v1.0.0 Beta 13 — Memory

> [!WARNING]
> **NOT HARDWARE TESTED.** This beta passes every automated check below, but
> it has **not been run on a physical Flipper Zero**. It answers the owner's
> beta 12 device log; every change and figure below comes from builds, host
> tests (the firmware's own decoders compiled on a PC) and a host model of
> the firmware's heap, **not from a device**. Successful compilation,
> simulation and CI are not device verification. Please run the
> [hardware checklist](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md#memory-and-relaunch-beta-13)
> items Y1–Y10 and report what you find. Use only on devices you own or are
> authorized to test.

## What's new

Beta 13 is a memory release. The owner's beta 12 log on RogueMaster
`4f2e0620` (API 88.4) showed three failures: reopening right after closing
(`Error loading section '.rgtext'`), Receive refused (`24704 free, session
took 36568`) and the RF Activity Logger refused after the Adaptive Scanner
(`radiogeddon_log.fal needs 17088, 13024 free`). Every feature is kept: all
16 of beta 12's modules, plus three new ones (19, module API 7), Dolphin
Lab, every analyzer, scanner and research tool, both editions. Transmit
restrictions are unchanged. Details and the source of every number:
[PERFORMANCE_BETA13.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/PERFORMANCE_BETA13.md).

### Smaller app, smaller blocks

| RogueMaster `4f2e06200` device build (built files) | Beta 12 | Beta 13 |
|---|---:|---:|
| Resident code and data | 84,812 B | **66,003 B (−22 %)** |
| Largest block a launch needs | 39,828 B | **13,492 B** |
| Second-largest | 31,148 B | 11,496 B |
| Relocation tables while loading (largest) | 23,764 B (10,469 B) | 20,629 B (4,737 B) |

- The Signal Database, the analysis menu (Multi-Compare, Smart Protocol
  Discovery, Decode), the Frequency Scanner's screen and the favorites
  screens are now modules, loaded only while used.
- The app's code is five sections of 8–13.5 KB instead of two of 40 and
  31 KB. On the host model of the loader, launches that fit right after an
  app closed rise from 31,643 to 83,569 of 126,000 heaps, with none lost.

### Receive

- About **10 KB less per session**: the firmware receiver used to allocate
  BinRAW's 10 KB decoder buffers, which the app's filter never feeds. Every
  decode is unchanged (all 1,358 decodes of the firmware's 51 test captures
  identical). Model on RogueMaster: 25.2 KB instead of 35.9 KB.
- A cost stored by beta 12 counts without those buffers until a new
  session measures its own, so the first Receive is not refused on the old
  figure.
- The check before Receive now also needs the worker's largest buffer in
  one free block, and that buffer is allocated first: on the heap model,
  beta 12's check let 298 of 18,000 split heaps start a session that then
  ran out; beta 13's none.

### Fixed

- **The Logger after the Adaptive Scanner**: the scanner was allocated
  while the setup screen's module was still loaded, so unloading it split
  the free heap. The model reproduces the device's `needs 17088, 13024
  free`; in beta 13's order the free heap stays in one block and the module
  loads (8,000 simulated rounds: 3,288 refusals → 0).
- **Receive opened from a tool screen** now checks memory after that tool's
  module is unloaded.

**The device-specific RogueMaster build** is compiled in the source tree of
RogueMaster commit `4f2e06200` (2026-10-01, API 88.4), the firmware of the
device that logged beta 12's memory failures. If *Settings → About → Firmware
Info* shows `4f2e0620 [88.4]`, use it; on any other RogueMaster build use
`radiogeddon-full-roguemaster.fap`. Copy only one of the two.

Copy the file to `SD Card/apps/Sub-GHz/` (replacing beta 12) and open
**Apps → Sub-GHz → RadioGeddon** (Catalog) or **RadioGeddon Full**.
Settings, recordings, sessions, the journal and the fingerprint index from
beta 12 keep working. Full steps:
[Installation](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/INSTALLATION.md).

> [!NOTE]
> Momentum and Official both report API 87.1, so the Flipper's version check
> does not tell the two files apart: install the one named for your firmware.

## Build & verification status (software only)

- Five builds from one source commit, each against its own pinned SDK or
  firmware tree, built from scratch. For every artifact the API version is
  asserted, the manifest checked and every imported symbol resolved against
  that firmware's `api_symbols.csv`; for the four Full builds the same holds
  for each of the 19 embedded modules.
- Host unit tests under AddressSanitizer and UBSan; the firmware's own
  Sub-GHz decoders on its test captures (including the decode-only receiver
  against the full one); format, capture, engine-lifecycle, fingerprint,
  activity-log, memory-stress and offline UI tests; ThreadSanitizer;
  libFuzzer on every file reader; firmware API contract checks; the code
  section of every function, in the source and the built app; module load
  cost on the built modules; the loader, module and flow replays on the heap
  model; GCC `-fanalyzer` and clang-tidy with no findings; clang-format.
- What these do **not** show: that the app opens again on a Flipper after
  closing, how much heap Receive takes on a device, or how RogueMaster's
  background services fragment the heap. The model reproduces the beta 12
  log's Logger sequence within about 800 B per step, but it is a model.
- Hardware: **NOT HARDWARE TESTED.**

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or
the per-file commands in the installation guide. Each `.fap` also has a
signed build-provenance attestation, checked by the release workflow before
upload, linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-full-roguemaster-4f2e06200-api88.4.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the edition, app id, SDK or firmware commit, API,
source revision and embedded modules of each artifact.

## Known limitations

- **Not hardware tested.** Y1–Y10 decide whether the relaunch and Receive
  failures are gone on the device.
- Five sections need five 1 KB checks: with almost no free heap, a launch
  can fail where four sections fit (a few simulated heaps); none where beta
  12 fits. The Catalog edition (six sections, +834 B) fits less often than
  beta 12 on 419 of 126,000 simulated heaps with barely enough free memory.
- Opening the Database, the Scanner, the analysis menu or the favorites now
  loads a module (a few tens of milliseconds); with very little memory left
  it says `Not enough memory` instead of opening.
- On RogueMaster (8 KB worker buffer) the new Receive check asks for a
  16.6 KB free block, so a few heaps that would fit are refused.
- The module check still sees only the largest free block.
- The device-specific RogueMaster file fits only commit `4f2e06200`.
- RadioGeddon does not recover keys, decrypt payloads, predict rolling codes
  or brute-force anything, and refuses to replay decoded rolling-code
  protocols.
