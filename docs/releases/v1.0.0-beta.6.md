## What's new

RadioGeddon now comes in **two editions** from one source tree, and gets its
first **Momentum** build. The full list is in the
[CHANGELOG](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/CHANGELOG.md).

- **RadioGeddon Full** (RogueMaster, Momentum, Unleashed) — everything RadioGeddon
  did before, plus:
  - **Range Scanner**: start / end / step sweeps of up to 256 points across
    every band the radio accepts, skipping the gaps it cannot tune; dwell,
    threshold, pause on hit, noise-floor recalibration, peak hold, counters,
    an estimated sweep time, CSV export, and long OK to receive and record at
    the cursor.
  - **Scan profiles**: save, load and delete named range setups (replacing
    one asks first).
  - **Favorites**: up to 24 frequencies; receive or record on one, or use the
    whole list as the Scanner's or the Hopper's frequencies.
  - **Fine frequency stepping** in Settings (1 kHz to 1 MHz, jumping over band
    gaps) and a **Radio bands** screen showing the receive bands the radio in
    use really accepts, measured from its driver, and the firmware region's
    transmit bands.
  - **Checksum structure hypotheses** in Unknown Protocol Analysis: whether
    the distinct frames of a capture end in an XOR, sum or CRC-8 of the bytes
    before, or a parity bit — reported only when it fits every distinct frame
    and there are enough of them for a chance fit to be unlikely.
  - Transmitting follows the installed firmware's own rules; the edition adds
    no regional restriction of its own.
- **RadioGeddon Catalog** (Official) — the receive and analysis toolkit, built
  for the Flipper Apps Catalog (submission in preparation, not in the catalog
  yet). Before any transmission it requires the firmware to know its region
  and the region to allow the frequency, and otherwise refuses with the reason
  on screen ("Region EU does not allow TX on 315.00 MHz"); the Replay screen
  says up front whether sending will be refused.
- **Momentum** is a first-class target: `radiogeddon-full-momentum.fap` is
  compiled against Momentum mntm-012's own SDK, whose Sub-GHz structures
  differ from Official's although both report API 87.1.
- **Both editions**: long OK on the Scanner opens Receive and starts a RAW
  recording at once; About shows the edition and the firmware's region.
- **Unknown Protocol Analysis** gets the base time unit right on all 50 of the
  firmware's RAW test captures (was 48) and the frame length on 33 (was 29):
  receiver glitches at 132 µs are no longer taken for Te, and repeats sent
  with no gap at all are cut to the bits' own period. Results stay
  `[HYPOTHESIS]`.

Recordings, settings, favorites and profiles live in
`apps_data/radiogeddon/` for both editions, so switching keeps them.

## Which file do I download?

| Firmware | Edition | File | API |
|----------|---------|------|-----|
| Official (flipperzero.one) 1.4.x | Catalog | `radiogeddon-catalog-official.fap` | 87.1 |
| RogueMaster | Full | `radiogeddon-full-roguemaster.fap` | 88.16 |
| Momentum mntm-012 | Full | `radiogeddon-full-momentum.fap` | 87.1 |
| Unleashed | Full | `radiogeddon-full-unleashed.fap` | 88.9 |

Copy it to `SD Card/apps/Sub-GHz/` and open **Apps → Sub-GHz → RadioGeddon**
(Catalog) or **RadioGeddon Full**. Updating from beta 5 on RogueMaster or
Unleashed: delete the old `radiogeddon-roguemaster.fap` /
`radiogeddon-unleashed.fap`, since the Full edition has its own app id. Full
steps: [Installation](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/INSTALLATION.md).

> [!NOTE]
> Momentum and Official both report API 87.1, so the Flipper's version check
> does not tell the two files apart: install the one named for your firmware.
> Official firmware **1.5.1** (still a release candidate) moves to API 88; the
> Catalog edition builds against the 1.5.1-rc SDK but no release targets it
> yet — see
> [Firmware Compatibility](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/FIRMWARE_COMPATIBILITY.md#newer-firmware).

## Build & verification status

- Built from one source tree as two editions for four firmware families, each
  against its own SHA-256-pinned SDK (RogueMaster from its pinned source
  tree); API version, manifest (edition name, version) and every imported
  symbol verified against that SDK for every artifact.
- 1,548 host unit-test checks under AddressSanitizer and UBSan, including
  both editions' switches, the transmit check in both editions, band probing
  against each firmware's real tuning ranges, range planning across gaps,
  checksum hypotheses (with CRC-8 catalogue vectors and 200 random trials
  without a false hit); 654 format checks that run the firmware's own file
  code on its 85 Sub-GHz test files, settings shared between editions,
  favorites and profiles; 289 decoder and preset checks on the firmware's own
  decoders and captures; 354 checks that score the analyzer on those
  captures; 23 lifecycle checks that start and stop the real Scanner, Range
  Scanner and Hopper engines 10 to 40 times each on real threads and count
  every allocation; libFuzzer runs on the RAW reader, analyzer, Pulse Timeline
  and Database; GCC `-fanalyzer` and clang-tidy over both editions with no
  findings; lint and documentation links clean.
- Apps Catalog checks for the Catalog edition, including the catalog's own
  bundler (clone, lint, build, manifest, icon, description, changelog):
  everything passes except screenshots, which must come from a real Flipper
  through qFlipper.
- Resident code (text, rodata, data, bss) is 75.6 KB for the Catalog edition
  and 94.5 KB for the Full edition, against 73.8 KB for beta 5; on the device
  this comes out of the same heap the radio uses. Measured from the built
  files, not on a device.
- Hardware: not verified for anything new since beta 2. The checks to run are
  in [HARDWARE_CHECKLIST.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md)
  (sections E, R, C and M are new) and
  [VERIFICATION.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/VERIFICATION.md).

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or the
per-file commands in the installation guide. Each `.fap` also has a signed
build-provenance attestation, checked by the release workflow before upload,
linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-full-momentum.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the edition, app id, SDK, API and source revision each
artifact was built from.

## Known limitations

- Nothing new since beta 2 is verified on a device yet; radio timing, SD-card
  speed and memory headroom on real hardware may surface problems the host
  tests cannot. The Full edition's larger code leaves about 21 KB less free
  heap than beta 5 did; the measured receive-session check still refuses a
  session that would not fit.
- A range sweep measures one frequency at a time: a burst shorter than a
  sweep can be missed on a point the sweep is not visiting. The screen shows
  the sweep time for this reason.
- The Catalog edition is not in the Apps Catalog yet: the submission needs
  qFlipper screenshots from hardware.
- The encoding Unknown Protocol Analysis reports is a hypothesis; its known
  misses are listed in
  [Protocol Analysis](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/PROTOCOL_ANALYSIS.md#what-it-cannot-do).
- RadioGeddon does not recover keys, decrypt payloads or predict rolling
  codes, and refuses to replay decoded rolling-code protocols.
