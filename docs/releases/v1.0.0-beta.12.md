RadioGeddon v1.0.0 Beta 12 — Stability

> [!WARNING]
> **NOT HARDWARE TESTED.** This beta passes every automated check below, but
> it has **not been run on a physical Flipper Zero**. The crash it fixes was
> found from the owner's beta 11 report and the firmware's source code; the
> fix, the memory layout and every figure below come from builds, host tests
> and a host model of the firmware's heap, **not from a device**. Successful
> compilation, emulation and CI are not device verification. Please run the
> [hardware checklist](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md#crash-and-relaunch-fixes-beta-12)
> items X1–X10 and report what you find. Use only on devices you own or are
> authorized to test.

## What's new

Beta 12 is a stability release. Every feature of beta 11 is kept: all 16
Full-edition modules (module API 6), Dolphin Lab, every analyzer, scanner
and research tool, both editions. Nothing in it transmits on its own. The
engineering record is
[STABILITY_BETA12.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/STABILITY_BETA12.md);
the full list is in the
[CHANGELOG](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/CHANGELOG.md).

### Fixed crashes

- **Scan → Adaptive Scanner → Start scanner stopped the device with
  `furi_check failed`** (reported on RogueMaster with beta 11). The setup
  screen cleared the list's enter callback with NULL when it closed, and
  every supported firmware `furi_check()`s that argument. The same bug was
  in the **RF Activity Logger** and **Database options** (the Catalog
  edition too). The shared list now always holds a resident do-nothing
  callback, so no screen can call code from an unloaded module either.
- **The Hopper's engine** no longer keeps a pointer to its screen's code
  after that module is unloaded.
- **Fingerprint index reader**: a record whose fingerprint's reserved bytes
  were not zero was accepted although the app never writes one (found by
  libFuzzer in CI). It is now refused; existing index files are unaffected.

### Memory layout optimization

Reopening the app right after closing it could fail for lack of RAM: the
firmware loads each code section into one heap block, and beta 11's code
was a single 70.9 KB section. The screens' code is now a second section
(`.rgtext`), so the largest block a launch needs is much smaller:

| Largest block a launch needs (built files) | Beta 11 | Beta 12 |
|---|---:|---:|
| Full edition (Unleashed) | 70,908 B | 39,824 B (−44 %) |
| Catalog edition (Official) | 70,260 B | 43,704 B (−38 %) |

The total code size is almost unchanged (+380 B Full, +571 B Catalog: the
memory checkpoints, the Scanner's pre-start check, the resident callback and
section alignment). On a host model of the allocator, launches that fit
after another app closed rose from 19,084 to 29,762 of 98,000 heaps; with
barely enough free heap in total (112 KB), beta 11 still fits slightly more
often (410 heaps). Simulation only — checklist X8–X9 is the device test.
Details: [PERFORMANCE_BETA12.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/PERFORMANCE_BETA12.md).

### Lifecycle safety

- The Scanner checks the largest free block before it allocates (firmware
  `malloc` stops the device instead of failing) and says `Not enough memory`.
- `RG.mem` log lines at launch, app start, each module load/unload, scanner
  start/stop, closing and exit: free heap, largest free block, lowest free
  heap, and at exit how much heap was not returned.
- `scripts/check_fw_contracts.py` (CI) checks every firmware call against
  the arguments the five pinned firmware trees `furi_check()`; it finds the
  three beta 11 calls and nothing else.
- New tests: the Adaptive Scanner driven 1,200 times as its screens do
  (ASan, TSan), and the app's launch replayed on fragmented heaps.

**New: a device-specific RogueMaster build.** RogueMaster changes its API
minor with almost every build. The fifth file is compiled in the source tree
of RogueMaster commit `4f2e06200` (2026-10-01, API 88.4), the firmware of
the device that reported the beta 11 crash. If *Settings → About → Firmware
Info* shows `4f2e0620 [88.4]`, use it; on any other RogueMaster build use
`radiogeddon-full-roguemaster.fap`. Copy only one of the two.

Copy the file to `SD Card/apps/Sub-GHz/` (replacing beta 11) and open
**Apps → Sub-GHz → RadioGeddon** (Catalog) or **RadioGeddon Full**.
Settings, recordings, sessions, the journal and the fingerprint index from
beta 11 keep working. Full steps:
[Installation](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/INSTALLATION.md).

> [!NOTE]
> Momentum and Official both report API 87.1, so the Flipper's version check
> does not tell the two files apart: install the one named for your firmware.

## Build & verification status (software only)

- Five builds from one source commit, each against its own pinned SDK or
  firmware tree. For every artifact the API version is asserted, the
  manifest (name, version 1.0) checked and every imported symbol resolved
  against that firmware's `api_symbols.csv`; for the four Full builds the
  same holds for each of the 16 embedded modules. The release package
  refuses artifacts built from different source revisions.
- 2,907 host unit-test checks under AddressSanitizer and UBSan (beta 11:
  2,903), plus 6.2 million exact-division checks; format, decoder, capture,
  engine-lifecycle (including the 1,200 Adaptive Scanner runs),
  fingerprint-index, activity-log file, memory-stress and offline UI tests;
  the threaded tests under ThreadSanitizer; libFuzzer on every file reader;
  the firmware API contract checker; module load cost checked on the built
  modules and replayed on fragmented heaps; GCC `-fanalyzer` and clang-tidy
  with no findings; clang-format lint; Markdown links.
- What these do **not** show: that the app runs on a Flipper, that the
  Adaptive Scanner no longer crashes on a device, or how much RAM it uses on
  one. The heap figures are a model of the firmware's allocator without the
  firmware's own background services.
- Previews in the README are **synthetic renderings** from the host canvas,
  not screenshots of a Flipper.
- Hardware: **NOT HARDWARE TESTED.**

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or
the per-file commands in the installation guide. Each `.fap` also has a
signed build-provenance attestation, checked by the release workflow before
upload, linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-full-roguemaster-4f2e06200-api88.4.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the edition, app id, SDK or firmware commit, API,
source revision and embedded modules of each artifact.

## Known limitations

- **Not hardware tested.** The crash fix is identified from source with no
  remaining alternative on that path, but is confirmed only by X1–X4 on a
  device. Whether the beta 11 relaunch failure was fragmentation alone is
  open: the `RG.mem` lines and the firmware's heap-trace balance (X7–X9)
  will tell.
- Two code sections need two blocks: with only just enough free heap in
  total, a launch can fail where beta 11's single block would have fitted
  (410 of 98,000 simulated heaps).
- The module check still sees only the largest free block, so a tool that
  would fit across several smaller blocks is refused (`Not enough memory`);
  restarting the Flipper defragments the heap.
- The device-specific RogueMaster file fits only commit `4f2e06200`; other
  RogueMaster builds should use the standard RogueMaster file or build their
  own (`RM_REF=<commit> RM_API=<api> scripts/build_target.sh full-roguemaster`).
- Similarity is evidence, not identity; the Adaptive Scanner's gains come
  from a host simulation; the activity logger observes one frequency at a
  time.
- The Catalog edition is not in the Apps Catalog yet: the submission needs
  qFlipper screenshots from hardware.
- RadioGeddon does not recover keys, decrypt payloads, predict rolling codes
  or brute-force anything, and refuses to replay decoded rolling-code
  protocols.
