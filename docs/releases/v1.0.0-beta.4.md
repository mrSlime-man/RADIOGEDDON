## What's new

Beta 4 fixes a crash found in beta 3 and adds one feature. The full list is in
the [CHANGELOG](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/CHANGELOG.md).

- **Fixed, Official firmware only: Receive and the Hopper could crash** when
  they decoded a **CAME Atomo** or **Alutech AT-4N** remote. Those two
  firmware decoders read the file name of a rainbow table, without checking
  it, when they describe a decode. RadioGeddon gives them none, because it
  does not undo rolling-code obfuscation. Those decodes are now listed by
  name, bit count and key, with a note that serial, button and counter need a
  table. Unleashed and RogueMaster check for a missing table and were not
  affected. The crash was found by the new decoder tests and has not been
  reproduced on a device. If you use beta 3 on Official firmware, update.
- **Decode with Firmware**: a new item in a RAW capture's Database menu. It
  runs the firmware's own protocol decoders, the ones Receive uses, over the
  whole saved recording, and lists each distinct decode once as
  `[CONFIRMED]`, with how many times and when in the recording it was decoded.
  A capture nothing decodes says so. The radio is not used. *Save report to
  SD* includes it for RAW captures.
- **Decoder tests in CI**: the firmware's Sub-GHz receiver and all its
  protocol decoders are built on the host from the pinned Official release.
  They run over the firmware's own 50 RAW test captures, fed the same way as
  in *Decode with Firmware*, and every capture decodes to the protocol the
  firmware's own test expects.

Settings and recordings stay where beta 3 put them
(`apps_data/radiogeddon/`).

## Which file do I download?

Install the build that matches your firmware. The others are safely refused by
the Flipper rather than loading.

| Firmware | File | API |
|----------|------|-----|
| Official (flipperzero.one) 1.4.x | `radiogeddon-official.fap` | 87.1 |
| Unleashed | `radiogeddon-unleashed.fap` | 88.9 |
| RogueMaster | `radiogeddon-roguemaster.fap` | 88.16 |

Copy it to `SD Card/apps/Sub-GHz/` (replacing the earlier beta) and open
**Apps → Sub-GHz → RadioGeddon**. Full steps:
[Installation](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/INSTALLATION.md).

> [!NOTE]
> Official firmware **1.5.1** (still a release candidate) moves to API 88, so
> `radiogeddon-official.fap` will not load on it. The app builds against the
> 1.5.1-rc SDK, but no release build targets it yet; see
> [Firmware Compatibility](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/FIRMWARE_COMPATIBILITY.md#newer-firmware)
> to build it yourself.

## Build & verification status

- Built for Official, Unleashed and RogueMaster from one source tree, each
  against its own SHA-256-pinned SDK; API version and `.fap` manifest verified
  for every artifact.
- 600 host unit-test checks under AddressSanitizer and UBSan; 562 format
  checks that run the firmware's own file code on its 85 Sub-GHz test files;
  213 decoder checks that run the firmware's own decoders on its 50 RAW test
  captures; libFuzzer runs on the RAW reader, analyzer, Pulse Timeline and
  Database; GCC `-fanalyzer` and clang-tidy with no findings; lint and
  documentation links clean.
- Hardware: not verified for anything new since beta 2. The checks to run
  are F4g (Decode with Firmware) and F5a (the crash fix) in the checklist; see
  [VERIFICATION.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/VERIFICATION.md).

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or the
per-file commands in the installation guide. Each `.fap` also has a signed
build-provenance attestation, checked by the release workflow before upload,
linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-official.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the SDK, API and source revision each artifact was
built from.

## Known limitations

- Nothing new since beta 2 is verified on a device yet; radio timing, SD-card
  speed and memory headroom on real hardware may surface problems the host
  tests cannot.
- *Decode with Firmware* finds what the firmware's decoders find. A frame cut
  off at the end of a recording, or in a stretch the recorder reported lost,
  may not decode.
- The encoding Unknown Protocol Analysis reports is a hypothesis. On the
  firmware's own test captures its frame length matches the decoded bit count
  for 8 of 33 paired captures, and is one bit short for 5 more.
- Unplugging an external module while receiving is not supported by the
  firmware's driver.
- RadioGeddon does not recover keys, decrypt payloads or predict rolling
  codes, and refuses to replay decoded rolling-code protocols.
