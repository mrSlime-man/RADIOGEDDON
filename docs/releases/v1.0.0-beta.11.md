RadioGeddon v1.0.0 Beta 11 — Memory & Performance

> [!WARNING]
> **NOT HARDWARE TESTED.** This beta passes every automated check below, but
> it has **not been run on a physical Flipper Zero**. Hardware testing is
> deferred until after this release; nothing here claims that any firmware
> has been verified on a device, and none of the memory figures below was
> measured on one. The only device report so far is for the beta 2 code on
> RogueMaster (it launches and works). Use only on devices you own or are
> authorized to test, and please report what you find with the
> [hardware checklist](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md)
> (section *Memory lifetimes and module loading*, V1–V8, is new).

## What's new

Beta 11 is a second optimization release, about the memory the app uses
while it runs rather than the size of its code. Every feature of beta 10 is
kept, unchanged: all 16 Full-edition modules, Dolphin Lab, every analyzer,
scanner and research tool, both editions and all four firmware builds.
Nothing in it transmits on its own. The full list is in the
[CHANGELOG](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/CHANGELOG.md).

- **Bitstream Explorer holds 4.5 KB less while open** — 4,072 B instead of
  8,672 B. The analysis result and the analyzer's working state are now
  separate, and the working state is freed as soon as the passes end. Pulse
  Studio, the Pulse Timeline and the reports benefit the same way.
- **Find Similar: exact, lighter, fewer card operations** — recordings are
  matched to the index by comparing names exactly (a hash only narrows the
  search, so two recordings can never be mistaken for one), with half the
  memory per recording, half the path lookups, a third of the folder
  listings when indexing, and each RAW file read 4 times instead of 6.
  Rankings are unchanged.
- **Database: more files in the same memory** — entries are 28 bytes
  instead of 40 and the index is one block; the 500-file cap became the
  memory beta 10's 500-file index used, which now holds about 600–660 files
  with typical names. Same order, search and duplicates.
- **Smarter module loading** — the memory checked before a tool opens is
  computed from that module's own file (including the relocation tables the
  firmware loads with it) instead of a flat allowance: 1.9–3.8 KB less for
  15 of the 16 modules, the safety margin unchanged.
- **No 64-bit division helper** — exact 64-bit division without the
  compiler's 698-byte routine, which was in the app and 8 modules; 14
  modules are smaller.
- **Memory stress testing** — a model of the firmware's heap allocator runs
  the heavy operations in CI: low memory (no allocation may fail), leaks and
  fragmentation over long sessions, module loads on fragmented heaps.

## Memory

Three different things, never mixed (details and method in
[Performance](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/PERFORMANCE.md)):

**Binary footprint** (code and static data, exact, from the built files):

| | Beta 10 | Beta 11 |
|---|---:|---:|
| Full edition, resident (Momentum) | 84,313 B | 84,433 B |
| Catalog edition, resident | 86,513 B | 86,565 B |
| Largest module | 23,620 B | 23,608 B |

**Heap objects** (device compiler's sizes):

| | Beta 10 | Beta 11 |
|---|---:|---:|
| Bitstream Explorer, held while open | 8,672 B | 4,072 B |
| Database entry | 40 B | 28 B |
| Find Similar, per tracked recording | 8 B | 4 B |

**Simulated runtime heap** (host model of the firmware's allocator, host
sizes; the same benchmark built against both versions):

| | Beta 10 | Beta 11 |
|---|---:|---:|
| Pulse Studio, held before its view | 10,240 B | 5,632 B |
| Find Similar peak, 1,000 recordings | 8,704 B | 5,536 B |
| Find Similar peak, 2,000 recordings, first search | 31,186 B | 15,856 B |
| Database, 1,000 files | 500 indexed | 662 indexed (same 32 KiB bound) |
| Module loads refused although they fit (fragmented heaps) | 24,817 | 20,865 |

Two small regressions, kept because they buy the larger gains: the resident
code grew by 120 B (Full) and 52 B (Catalog), and Find Similar on a library
of about 100 recordings peaks 320 B higher (a fixed 250-byte bitmap).

## Build & verification status

- Built from one source tree as two editions for four firmware families, each
  against its own SHA-256-pinned SDK (RogueMaster from its pinned source
  tree). For every artifact the API version, the manifest and every imported
  symbol are verified against that SDK; for the Full builds the same holds
  for each of the 16 embedded modules.
- 2,903 host unit-test checks under AddressSanitizer and UBSan (beta 10:
  2,756), plus 6.2 million exact-division checks; the new memory stress
  tests on the heap model (no failed allocation in 764 low-memory steps, no
  leak, the free space whole again after 4,000 random operations); module
  loads replayed on 64,000 fragmented heaps and 20,000 load/unload cycles;
  701 format checks, 339 decoder and preset checks, 407 analyzer checks on
  the firmware's captures, 43 engine lifecycle checks, 103 fingerprint-index
  checks, 31 activity-log file checks, 426 offline UI checks, the threaded
  tests under ThreadSanitizer (no reports), libFuzzer on every file reader,
  and GCC `-fanalyzer` and clang-tidy with no findings.
- Previews in the README are **synthetic renderings** from the host canvas,
  not screenshots of a Flipper.
- Hardware: **NOT HARDWARE TESTED.** The checks to run are in
  [HARDWARE_CHECKLIST.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/HARDWARE_CHECKLIST.md)
  and [VERIFICATION.md](https://github.com/mrSlime-man/RADIOGEDDON/blob/main/docs/VERIFICATION.md).

## Verifying these downloads

`SHA256SUMS` is attached. Check it with `sha256sum -c SHA256SUMS` (Linux) or the
per-file commands in the installation guide. Each `.fap` also has a signed
build-provenance attestation, checked by the release workflow before upload,
linking it to this release's workflow run and commit:

```bash
gh attestation verify radiogeddon-full-momentum.fap --repo mrSlime-man/RADIOGEDDON
```

`BUILD_INFO.txt` records the edition, app id, SDK, API, source revision and
embedded modules each artifact was built from.

## Known limitations

- **Not hardware tested**, and no runtime memory figure was measured on a
  device: the heap figures come from the device compiler's sizes and a host
  model of the allocator. About's free heap and lowest point on a device are
  the figures to report (checklist V1, V6, V7).
- The module check still sees only the firmware's largest free block, so a
  tool that would fit across several smaller blocks is refused (`Not enough
  memory`); restarting the Flipper defragments the heap.
- The Activity Heatmap's grid is unchanged (up to 9 KB for 24 frequencies):
  a smaller cell would lose measurement precision.
- Similarity is evidence, not identity; the Adaptive Scanner's gains come
  from a host simulation; the activity logger observes one frequency at a
  time.
- The Catalog edition is not in the Apps Catalog yet: the submission needs
  qFlipper screenshots from hardware.
- RadioGeddon does not recover keys, decrypt payloads, predict rolling codes
  or brute-force anything, and refuses to replay decoded rolling-code
  protocols.
